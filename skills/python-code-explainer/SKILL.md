# Python 代码解读（生成带注释的注解版 .py 文件）

## 目标

把用户提供的 Python 代码（粘贴的代码片段、单个文件，或项目下的一批文件）解读为一份**仍然是合法 Python 文件**的注解版输出。输出文件的结构固定为三段：

1. **文件开头**：整个文件的功能定性 + 详细中文介绍（UTF-8 编码）
2. **文件主体**：每个最小代码块之后紧贴具体的中文注释
3. **文件结尾**：代码不足与可优化方向

## 工作流程

### 第一步：通读

- 若代码来自文件路径：用 read 工具完整读取（大文件分多次读完，不要只看片段就下结论）。
- 若代码是粘贴在对话里的：先整体通读一遍再动手。
- 通读时确认：文件是模块 / 脚本 / 包？入口在哪（是否有 `if __name__ == '__main__'`）？依赖哪些标准库与第三方库？核心数据结构与算法是什么？输入输出是什么？被谁调用或调用谁？

### 第二步：确定输出文件

- 输入为文件 `foo.py` 时，输出到**同目录**下的 `foo_annotated.py`。
- 输入为粘贴代码时，与用户确认输出文件名（默认 `annotated_code.py`，放在当前工作目录）。
- 处理“项目下所有代码文件”时：递归扫描项目下所有 `*.py`，**跳过**已经注解过的文件（文件名含 `_annotated`）、虚拟环境与依赖目录（`.venv`、`venv`、`site-packages`、`__pycache__`、`node_modules` 等），对每个文件生成一个对应的 `xxx_annotated.py`。

- **当前文件夹模式（删除旧文件）**：当被解读的代码来自**磁盘上已有的文件**（尤其是当前工作目录 / 当前文件夹内的文件，而非对话中粘贴的代码）时，在注解版文件成功写出**并通过语法校验**之后，**删除原始代码文件**。删除的硬性前提：
  - 注解版文件已成功写入且 `py_compile` 通过——任何一步失败都**绝不删除**原文件，并保留原文件向用户报告；
  - 只删除被解读的那一个原始文件，绝不触碰其他文件；
  - 删除后向用户汇报已删除的文件名。

### 第三步：生成注解版文件

**铁律：输出必须是可编译的合法 Python 文件——只加注释，不改动原代码的逻辑、命名与行为**（除非用户明确要求重构）。

#### 1. 文件头（功能定性）

- 若原文件有 `# -*- coding: utf-8 -*-`，输出文件第一行保留它。
- 紧跟一个模块级 docstring 或成块的 `#` 注释（用 `# ===...===` 分隔线分节），必须包含：
  - 文件路径 / 名称
  - 一句话功能定性：这个文件“是什么、干什么”
  - 详细展开：模块职责、主要类与函数一览、输入输出、外部依赖、运行入口、关键设计（数据结构 / 算法 / 设计模式 / 全局状态）、与外部模块的关系
- 头部要“详细”，但不许啰嗦——用分节列表而非大段散文。

#### 2. 逐块注释

把代码切分为“最小但有具体含义的代码块”，每个块**之后紧贴**添加中文注释：

- **导入区**：整段导入之后加一块注释说明各导入用途；关键导入可加行尾注释。
- **模块级常量 / 配置**：每个常量（或一组同义常量）后加注释，说明含义、单位、取值范围、被谁使用。
- **类定义**：类头后加注释说明类职责、关键属性、关键方法；每个方法定义后加注释说明职责、参数、返回值、副作用、边界情况。
- **函数定义**：函数头后加注释说明功能、参数、返回值、异常、时间复杂度（如 O(n)）。
- **函数内部**：按逻辑段（输入校验 → 初始化 → 主逻辑 → 分支 → 收尾）逐段注释；每个 `if/elif/else`、`for/while`、`try/except`、`with`、列表推导式、lambda、`yield` 都作为独立块，在其后注释判断依据、循环目的、异常处理策略、资源管理意图。
- 单行琐碎表达式可以不加注释，但一行内含多个动作时要在行尾注释拆解。
- 注释一律中文，`#` 后空一格；注释解释“**为什么 / 做什么**”，不要复述代码字面（禁止“这行把 a 赋给 b”这类废话注释）。

#### 3. 文件尾（不足与可优化方向）

在文件末尾追加一节 `# === 代码不足与可优化方向 ===`，从以下角度逐条给出**具体、可执行**的建议（每条注明：问题位置 → 原因 → 改法）：

- 可读性与结构：命名、魔法数字、过长函数、重复代码、职责划分
- 性能：时间复杂度、循环内重复计算、不必要的拷贝、I/O 与缓存
- 健壮性：异常处理粒度、边界条件、空值 / 类型假设、资源释放
- 安全性：路径穿越、注入、敏感信息硬编码
- 测试与维护：缺少单测、缺少类型注解、缺少日志
- 兼容性：Python 版本特性、第三方库版本锁定

### 第四步：校验

- 输出文件写入后，若环境可用，用 `python -m py_compile <输出文件>` 做一次语法校验；失败则修正后重跑。
- 复核清单：文件头是否完整详细；是否每个最小代码块都有注释；结尾优化建议是否存在；原代码是否被意外改动。
- 注解版通过语法校验后，若本次解读的代码来自磁盘文件（当前文件夹模式），按第二步的规则删除原始代码文件，并向用户确认删除结果。

## 边界与注意

- 本 skill 只解读 Python 代码；用户给其他语言时明确说明适用范围（用户坚持时可类比套用，但需声明）。
- 注解版必须能通过语法编译：注释不得影响运行，不得改变原代码行为。
- 大文件也必须逐块注释完整，不允许跳过中间部分或只注释开头结尾。
- 处理整个项目时按文件逐个生成，完成后向用户汇总生成了哪些文件、每个文件的注解概况。
- **破坏性操作边界**：删除原始文件仅在“注解版成功写出 + 语法校验通过”之后执行；写出失败、校验失败或用户未明确要求时一律保留原文件。
