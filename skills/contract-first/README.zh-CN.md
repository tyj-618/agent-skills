# Contract First

`contract-first` 是一个可移植的 Skill：写实现之前先产出一份可审查的契约（范围、接口、错误码、验收与非目标），并在契约被接受前停下来。

English: [README.md](README.md)

## 它能做什么

先把约定写清楚，再动代码：

- 用一句话重述需求。
- 写明范围、非目标、接口；每种错误给出稳定的错误码和分类；验收写清用哪条命令、什么输入、期望什么输出。
- 写完即停，等批准。
- 只实现已接受的契约，并记下每条验收实际跑过的命令和输出。
- 实现中发现缺口，就先改契约，再次征求批准。

## 为什么需要它

“做完”还没说清时，Agent 会用代码把空缺填上。被审查的是契约，实现跟在后面。审查者不用先读 diff，就能判断范围、输入输出和错误。

## 何时使用

- 新功能、工具、API 或行为变更，“完成”仍说不清。
- Agent 习惯在接口谈妥之前就动手写。
- 结果要交给另一个人或另一个 Agent 审查。

## 在编程 Agent 中使用

1. 将当前 Skill 文件夹复制到目标编程 Agent 支持的 Skills 目录。
2. 描述功能，并要求 Agent 使用 `contract-first`。
3. 审契约。接受，或打回修改。
4. 接受之后，再让 Agent 只实现契约覆盖的部分，并逐条验收。

可直接使用的指令：

> 请使用 `contract-first` Skill。用一句话重述需求，写出契约，然后停下。我接受之前不要写实现代码。实现中如果发现契约有缺口，先改契约并再次征求同意，再继续。

## 规则

- 契约被接受之前，不写实现代码。
- 契约是依据；和它冲突的代码就是错的。
- 非目标写清楚，用来挡住范围蔓延。
- 每种错误都要有稳定的错误码和分类。
- 验收必须能核对：一条命令、一份输入、一份预期输出。
- 需求含糊就问，不要自己补需求。
- 实现中露出契约缺口时，停下来改契约，重新取得批准。
